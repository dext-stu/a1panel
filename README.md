# a1panel — AI 运维面板

一个由 AI 亲手编写的服务器运维面板。面板本身只提供登录、执行与展示的骨架；**左侧每一个运维模块，都在你首次点开时由模型现场生成，然后永久保留**。生成的不是只读监测卡，而是能真正操作的整页(列容器带启停/重启/删除、进程带结束、证书带续期……)。

> Node.js ≥ 20，零依赖(仅用内置模块 + 全局 `fetch`)。

## 运行

```bash
node server.js
```

打开 http://127.0.0.1:7070

## 三步

1. **登录** — 首次启动时，服务在终端打印一次**初始登录密码**，首次打开登录页也显示一次；此后磁盘只保留 scrypt 哈希(`auth.json`)。忘记密码：删除 `auth.json` 重启即重新生成。
2. **连接模型** — 填写 Base URL / API Key / 模型。默认 Base URL 为 `https://ai.dext.top`（可用环境变量 `A1_BASE_URL` 改，或直接填官方 `https://api.anthropic.com`），**不强制 Anthropic**：任何兼容 Anthropic Messages API 的网关都可以填，模型可自定义。连接（Base URL / Key / 模型）保存在本机 `connection.json`（不入库），**重启不丢**；只有登录会话会过期，需重新登录。进面板后可用左下角「修改 API」随时改地址/模型/Key（Key 留空则沿用当前）。
3. **点开左侧模块** — 概览 / Docker / 网站与证书 / 进程 / 服务 / 网络与端口 / 磁盘与文件 / 计划任务 / 系统日志。**点开哪个，AI 才生成那个**(全程流式，能看到它实时"思考 + 写代码")，生成完永久保留在 `modules.json`，下次秒开。也可「＋ 新建模块」用一句话定制。

## 一个模块 = AI 写的三段代码

- `collect(ctx)` — 在**服务端**执行，用 `ctx.{os, fs, path, platform, exec}` 读取真实系统信息。
- `actions[name](ctx)` — 在**服务端**执行**操作**(重启服务、结束进程、清理、续期……)，`ctx.args` 是按钮带的参数。破坏性操作前端会二次确认。
- `render(data)` — 在**浏览器**渲染整页；操作按钮用统一约定 `data-action="名字" data-args='{...}' data-confirm="确认文案"`，点击即回到服务端执行对应 action，然后自动刷新。

顶部工具：**刷新**(重跑 collect)、**重写**(让 AI 换一版实现，可附不满意原因)、**删除**(预置模块删除后下次点开会重新生成)。

## 边界与安全

- 登录是**确定性的密码网关**(服务端实现，非 AI 生成)，登录后所有接口都需要会话 Cookie。
- 面板会**执行 AI 生成的代码**来读取并**操作**本机——这是它工作的原理，也意味着比只读更需谨慎。请**只在你自己的机器上运行，不要暴露公网**。collect/action 有超时保护，破坏性操作有二次确认。
- 诚实说明：这是"形似 1Panel、覆盖常用运维动作"的方案，达不到 1Panel 那些成熟专用模块(Docker/网站/证书/应用商店)的完整度与精致度；某个组件(docker/nginx/certbot)没装时，模块会显示"未检测到"空状态。

## 环境变量

`A1_PORT`(默认 `7070`)、`A1_HOST`(默认 `127.0.0.1`)、`A1_BASE_URL`(默认 Base URL)、`A1_DATA_DIR`(运行时状态 auth/modules/connection 的存放目录，默认项目目录)。

## 文件

- `server.js` — 服务端(HTTP、登录、模型调用、代码执行引擎、模块持久化)，零依赖
- `public/index.html` — 前端(登录 / 连接 / 侧边栏面板三屏)，浅色米白 Claude 风、无 emoji
- `auth.json` — 登录凭据(盐 + 哈希)，首次运行生成，**不入库**
- `modules.json` — 已生成的模块定义，**不入库**
- `connection.json` — 保存的连接(Base URL / 模型 / API Key)，**不入库**；含明文 Key，仅供本机自用
